## Task 4

- `src/lib/bm25.js:23` — The constructor throws a RangeError for malformed locale tags that browsers and pages often report, such as 'en_US' (verified: 'Incorrect locale information provided'). - `src/lib/bm25.js:28` — /^\d+$/ only matches ASCII digits, so full-width or other Unicode digit runs are kept as tokens (verified: tokenize('Acme ２０２４ x') returns '２０２４'). The brief says to drop tokens that are all digits.
- `src/lib/bm25.js:81-82` — Bigrams are built from neighbouring word tokens after punctuation segments are thrown away, so they join words across title separators. For example 'Invoice - Gmail' gives 'invoice gmail', and the test data gives 'march the'. Such cross-separator phrases can reach the candidate list.
- `test/bm25.test.js:147-158` — No test covers a bigram with a common word, the case where the code departs from the brief. Nothing tests the max cap or the descending score/tie order of candidateTerms either.
- `src/lib/bm25.js:65` — A bigram is formed only when both words pass the document filter (at least minDocs tabs and no more than half). The brief applies that filter to the bigram's own frequency. As a result, phrases whose first word is common in your tabs can never appear. Probe: 'Budget - Google Sheets' and 'Plan - Google Sheets', plus three other Google tabs among 8, give ['sheets'] and never 'google sheets'. This degrades gracefully (the unigram survives), and the report documents it as deliberate. It still differs from the brief's interface.
- `src/lib/bm25.js:11` — The all-digits check uses /^\d+$/ without the u flag, so it only matches ASCII digits. Full-width or other Unicode digit runs survive as tokens: tokenize('２０２４ 年 report') returns ['２０２４', '年', 'report']. The CJK test at line 12 also has no u flag, so single astral Han characters (for example 𠮷, U+20BB7) are dropped as 'one character, not CJK'.
- `test/bm25.test.js:132` — The candidateTerms test passes only because every title contains ' - the ', and 'the' fails the frequency filter, which blocks the false bigram across the separator. Remove 'the' and the same fixture would join words across the dash. The tests never cover separators or dropped tokens between words, nor a mixed-language set, so the two important defects above go undetected.
